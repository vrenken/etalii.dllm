# Verifiable text watermarks

A watermark lets whoever holds a key tell, from the text alone, that it was generated by this engine with that key.
EtAlii.Dllm uses the soft watermark of Kirchenbauer et al. (2023, "A Watermark for Large Language Models") with every
step defined in integers. So:

- The same request with the same key gives the same bits on every machine, like every other answer.
- Detection is exact: the same text and key give the same green count and z-score everywhere.
- Watermarked answers replay from their [receipts](receipts.md), and the independent
  [reference implementation](specification.md) repeats the watermark bit for bit.

## How it works

After each token, a key-dependent rule splits the vocabulary into a *green* list (a fraction `gamma`, 0.25 by
default) and the rest. Generation adds `delta` (2.0 by default) to the logits of the green tokens, so the model
prefers them where it has a choice. Detection counts how many tokens of a text are green after the token before
them. Ordinary text has about `gamma` of its tokens green; watermarked text has many more.

The exact rule (also in [the specification](specification.md#4-random-numbers-and-sampling)):

1. `K` is the first 8 bytes (little-endian) of `SHA-256("dllm-watermark/1\0" + key)`, the key in UTF-8.
2. `mix(z)` is the SplitMix64 finalizer, modulo 2^64:
   `z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9`, `z = (z ^ (z >> 27)) * 0x94D049BB133111EB`, `z ^ (z >> 31)`.
3. After the token `p` (the last prompt token for the first answer token, -1 without a prompt), with
   `G = 0x9E3779B97F4A7C15`, the seed is `s = mix(K + (p + 1) * G)`, and token `t` is green when
   `mix(s + (t + 1) * G) < floor(gamma * 2^64)`.
4. Generation: `x = f32(x + f32(delta))` for every green token, after logit bias and penalties, before greedy
   selection or sampling.
5. Detection over `n` scored tokens with `g` green: `z = (g - gamma * n) / sqrt(n * gamma * (1 - gamma))` in double.
   The text counts as watermarked when `z >= 4` (a false positive rate near 3e-5 per text).

A larger `delta` makes the watermark easier to detect in fewer tokens and changes the text more; a short answer or
one where the model has little choice (a fixed fact, code) carries little signal. The watermark survives copying but
not rewording: detection tokenizes the text with the generating model's tokenizer, so edited or retokenized text
scores lower.

## Generating

```bash
dllm generate --prompt "Write a short story" --temperature 0.8 --seed 1 --watermark-key my-secret
dllm chat --watermark-key my-secret --watermark-delta 3 "Tell me a story"
```

Over the APIs (`gamma` and `delta` are optional):

| API | Field |
| --- | --- |
| OpenAI chat completions | `"watermark": {"key": "my-secret", "gamma": 0.25, "delta": 2.0}` |
| Anthropic messages | `"watermark": {"key": "my-secret"}` (an extension) |
| Ollama `options` | `watermark_key`, `watermark_gamma`, `watermark_delta` |

The key is part of the request: it changes the response id and is recorded in the receipt (only when set, so
receipts without a watermark keep their bytes). Keep the key as secret as you need detection to be; anyone with it
can detect, and could also try to avoid, the watermark.

## Detecting

```bash
dllm watermark detect answer.txt --key my-secret          # prints green tokens, z and the verdict
dllm watermark detect - --key my-secret --json < answer.txt
```

The exit code is 0 for watermarked text, 1 for unwatermarked text and 2 for an error. The served model's tokenizer
is used, so pass the same `--model` that generated the text. Over HTTP:

```bash
curl -s localhost:5080/v1/watermark/detect -H 'content-type: application/json' \
  -d '{"text": "...", "key": "my-secret"}'
# {"tokens": 41, "green": 30, "z": 7.123, "watermarked": true, "gamma": 0.25, "threshold": 4.0}
```

Detection only reads the text; it needs the tokenizer but not the model's weights. The first token of the text is
not scored, since the token before it (the end of the prompt) is unknown. In Python,
`etalii_dllm.watermark.detect(tokens, key, previous=last_prompt_token)` scores it too.

## Golden values

`tests/test_watermark.py` pins the fingerprint of a watermarked answer and of its detection
(`tests/golden_values.py::WATERMARK_FINGERPRINTS`), and the conformance vectors carry two watermarked sampling cases
(`sample-watermark`, `sample-watermark-greedy`), so other implementations can check their green lists.
